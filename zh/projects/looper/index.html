项目 01 / 可插拔 Agent Runtime

Looper.

一个从经过验证的 Rust Core 演进而来的完整、可插拔 Agent Runtime，用稳定接口让真实产品接入自己的能力。

为什么存在。

当模型调用、状态变更、流式输出与副作用坍缩进一个不透明的函数时，Agent 系统会变得难以推理。

Looper 把这些职责拆进一个可见的执行生命周期。当前仓库从单个 session、单次前台运行、一个内存事件存储和模拟模型效果开始——这是第一个经过验证的实现切片，不是最终产品范围。

目标是完整的 Runtime 模块：Core 保持执行语义自洽，扩展接口让真实业务应用无需 fork 或重写循环就能替换能力。

Core 与扩展。

Core 拥有不变量；扩展拥有产品之间必须变化的部分。

Core / 稳定的执行模块

一个覆盖完整生命周期的小接口。

Core 负责 session 与 run 状态、命令排序、纯决策、持久事实、效果调度、事件发布与恢复语义。

正在运行
单 session Mailbox、纯决策与 Reducer、内存 Event Store、Event Bus 与模拟效果。
演进目标
持久化恢复、取消、多 session 监督、重试，以及在同一个 Runtime 接口背后拒绝迟到结果。
扩展 / 可替换的 Adapter

真实能力在明确的 seam 上接入 Core。

产品为外部与业务特定行为注入 Adapter。Looper 定义生命周期契约与错误模式；每个应用选择具体实现。

已有证明
模拟模型、内存存储、CLI、HTTP/SSE 与 React 检视 Adapter。
演进目标
面向生产 Adapter 与插件的版本化发现、配置、隔离、健康、升级与优雅下线。

扩展接口。

每个接口描述调用方在它的 seam 上必须知道什么。Adapter 可以更换，而不会把 provider 或部署复杂度泄漏进 Core。

01 / 切片已存在

Model

推理、流式增量、完成、用量元数据、取消与 provider 错误。当前证明使用模拟流式 Adapter；真实 provider 是下一步。

02 / 契约已规划

Tool

能力发现、schema 校验、执行、进度、结果与失败，面向本地工具、MCP 服务器或产品自有动作。

03 / 内存 Adapter 已存在

Memory / Storage

当前 Event Store 在内存中。接口将支持持久化 session 事件、快照、工件，以及可选的长时记忆实现。

04 / 流已存在

Event

有序的运行时事实与临时进度，供 UI 订阅者、审计日志、指标、trace、索引与产品工作流使用。

05 / 契约已规划

Policy

权限、预算、审批、沙箱要求、组织规则，以及允许、拒绝或暂停某个效果的决策。

06 / Adapter 已存在

Transport

CLI 与 HTTP/SSE 今天已经证明这个 seam。未来的 Adapter 可以暴露 JSON-RPC、队列、worker 或应用特定接口。

运行闭环。

每个被接受的命令都走完同样的一组显式阶段。

  1. 01Mailbox

    为单个 session actor 串行化命令与已完成的效果。

  2. 02decide()

    根据当前状态与输入纯计算领域事件与请求的效果。

  3. 03Event Store

    先持久化持久事实；原型使用内存 Adapter。

  4. 04Reducer

    应用已存储事件重建 session 的内存状态。

  5. 05Event Bus

    向订阅者发布持久事实与临时流式增量。

  6. 06Effect Runner

    执行请求的工作并把结果送回 Mailbox，闭环结束。

今天已运行的能力。

当前里程碑证明最小 Core 闭环及其第一批 Adapter。它尚未宣称具备完整的生产级 Runtime。

  • 类型化的 command、run、effect、session 与 event 标识符。
  • 一个纯决策函数与带领域焦点测试的 Reducer。
  • 一个 Tokio Mailbox、命令接收、广播 Event Bus 与模拟流式 Effect Runner。
  • 一个打印持久事件与实时增量的 CLI。
  • 一个 Axum HTTP/SSE Adapter 与一个 React Runtime Inspector。

真实业务集成。

Looper 是无头 Runtime 模块，不是预先选定的业务 Agent。

01

产品拥有领域。

编码助手、浏览器操作器、数据诊断 Agent 或实验运行器定义自己的工作流、prompt、数据、UI 与业务规则。

02

Adapter 带来真实能力。

产品在 Looper 的扩展 seam 上提供 Model、Tool、Memory 或 Storage、Event、Policy 与 Transport Adapter。

03

Core 保持执行自洽。

Looper 在每一条业务集成上拥有生命周期、顺序、状态转换、效果、恢复语义与可观察事件。

接下来做什么。

这些里程碑加深现有 Core，并把已规划的扩展 seam 变成生产就绪接口。它们是路线图事项，不是当前能力声明。

  • 持久化 Storage Adapter、快照、恢复与重放。
  • 带取消与结构化失败的生产 Model 与 Tool 接口。
  • 面向业务应用的 Memory、Event sink 与 Policy Adapter。
  • 多 session 监督、迟到结果拒绝、重试与优雅关闭。
  • 带版本化协议契约的进程外插件发现与隔离。

Core 优先。在业务差异处扩展。
